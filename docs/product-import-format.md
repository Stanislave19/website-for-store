# Формат файлу масового імпорту товарів

> Стосується `POST /api/admin/products/import` та сторінки адмінки `/admin/products/import`.
> Готовий шаблон з актуальними колонками можна завантажити на цій сторінці або напряму: `GET /api/admin/products/import/template`.

## Формат файлу

- `.csv` (кодування UTF-8, у т.ч. з BOM — так зберігає Excel за замовчуванням) або `.xlsx`.
- Перший рядок — заголовки колонок, точно як у таблиці нижче.
- Кожен наступний рядок — один товар.

## Колонки

| Колонка | Обов'язкова | Формат / приклад |
|---|---|---|
| Назва | так | текст |
| Опис | ні | текст |
| Ціна | так | число, невід'ємне (напр. `2400` або `2400.50`) |
| Стара_ціна | ні | число; порожньо — без знижки |
| Артикул | так | унікальний текст — **ключ для оновлення** (див. нижче) |
| Категорія | так | точна назва **існуючої** категорії (регістр не важливий) |
| Бренд | так | назва — знаходить існуючий або створює новий |
| Тип_механізму | так | назва — знаходить існуючий або створює новий |
| Стать | так | `Чоловічі` / `Жіночі` / `Унісекс` |
| Діаметр_мм | ні | число, дробова частина через кому або крапку (напр. `38` або `38.5`) |
| Товщина_мм | ні | число, дробова частина через кому або крапку (напр. `9` або `9.2`) |
| Комплектація | ні | текст |
| Активний | ні | `так` / `ні` (порожньо = `так`) |
| Фото | ні | URL-адреси фото через `;` (напр. `https://.../1.jpg;https://.../2.jpg`), перша — головна |

**Будь-яка інша колонка**, чия назва точно збігається з назвою наявного типу атрибута в адмінці (напр. «Матеріал корпусу», «Скло», «Функції», «Тип індексів»), автоматично трактується як значення цього атрибута. Кілька значень — через `;` (це особливо важливо для «Функції», де товар може мати кілька одночасно). Значення знаходить існуюче або створює нове в межах цього типу атрибута. Невідомі колонки, що не збігаються з жодним типом атрибута, просто ігноруються — не викликають помилку.

## Гарантія — не колонка файлу

`Гарантія_міс` навмисно **відсутня** серед колонок імпорту. Гарантія — загальна умова магазину (єдиний термін на весь асортимент, узгоджується напряму з постачальником), а не властивість конкретної моделі, тому в файлі прайс-листа її не буде і CSV її не читає.

Замість цього імпорт завжди підставляє константу `DEFAULT_WARRANTY_MONTHS = 12` (12 місяців) у `warranty_months` для кожного товару — і при створенні, і при оновленні через повторний імпорт. Значення файлу тут ролі не грає, бо колонки просто немає.

## Категорія: чому без автостворення

На відміну від бренду, типу механізму й значень атрибутів, **категорія не створюється автоматично**. Якщо в колонці «Категорія» вказано назву, якої немає серед наявних категорій, — рядок піде в помилки. Спочатку створіть категорію в адмінці (`/admin/categories`), потім імпортуйте товари. Причина: категорії — це таксономія каталогу, автоматичне створення з друкарської помилки в файлі (напр. «Класична» замість «Класичні») непомітно засмітило б структуру каталогу.

## Оновлення наявних товарів (upsert за артикулом)

- Якщо товар з таким **Артикулом** вже є в базі — його дані оновлюються.
- Якщо артикула ще немає — створюється новий товар.
- Це дозволяє повторно імпортувати той самий (оновлений) файл без побоювання створити дублікати.

## Фото при повторному імпорті

Фото з колонки «Фото» довантажуються **лише якщо в товару ще немає жодного фото**. Якщо товар уже має хоча б одне фото (додане вручну чи попереднім імпортом), колонка «Фото» при повторному імпорті ігнорується — це запобігає накопиченню дублікатів фото при регулярному оновленні прайсу постачальника. Щоб замінити фото — видаліть наявні вручну в адмінці, потім імпортуйте файл ще раз.

Обмеження на фото з посилань:
- лише `http`/`https`;
- заборонені посилання на приватні/локальні адреси (захист від зловживання);
- редиректи не підтримуються — посилання має вести напряму на файл зображення;
- максимальний розмір файлу — 8 МБ;
- формат — `.jpg`, `.jpeg`, `.png` або `.webp` (визначається за Content-Type відповіді або розширенням у посиланні);
- **вміст файлу перевіряється як зображення** (Pillow відкриває байти й викликає `verify()`), незалежно від того, що показують Content-Type чи розширення в посиланні — файл, перейменований під `.jpg`, але не є коректним зображенням, буде відхилений з помилкою «Файл пошкоджений або не є зображенням».

Якщо конкретне фото не вдалось завантажити (недоступне посилання, завелике, не той формат) — **сам товар усе одно створюється/оновлюється**, а помилка фото йде окремим рядком у звіті.

## Обробка помилок у рядках

Імпорт **частковий**: валідні рядки обробляються незалежно від помилкових. Кожна помилка в звіті вказує номер рядка **так само, як він виглядає у файлі** (рядок 1 — заголовки, перший товар — рядок 2), і опис проблеми українською (напр. «Категорію «X» не знайдено — спершу створіть її в адмінці», «Поле «Ціна» має бути числом»).

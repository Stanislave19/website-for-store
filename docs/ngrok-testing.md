# Тестування через ngrok

Тимчасовий спосіб відкрити локальний сайт назовні (напр. перевірити на реальному телефоні), не тримаючи це як постійну конфігурацію.

## Увімкнути

```
./scripts/ngrok-on.sh
ngrok http 80
```
Скрипт сам ставить `NEXT_PUBLIC_API_URL=/api` у `.env` (щоб браузер телефону стукався в API через той самий ngrok-домен, а не в `localhost:8000`, якого на телефоні немає) і додає `allowedDevOrigins` у `frontend/next.config.ts` (без цього dev-сервер Next.js блокує запити з чужого origin). Відкрий адресу, яку видасть ngrok, на телефоні.

## Вимкнути

```
./scripts/ngrok-off.sh
```
Повертає `.env` і `next.config.ts` точно до стану, який був до `ngrok-on.sh` (з резервної копії, не з захардкодженого значення), і перезапускає frontend. Онов сторінку в браузері після цього.

## Якщо щось пішло не так

- `ngrok-on.sh` відмовляється запускатись повторно, поки не викликано `ngrok-off.sh` (захист від перезапису бекапу вже зміненим `.env`).
- `ngrok-off.sh` відмовляється запускатись, якщо бекапу немає — нічого не ламає, просто нічого не робить.
- Резервна копія лежить у `.env.ngrok-backup` (у `.gitignore`, у git не потрапляє).
- Безкоштовний ngrok видає домен з різним закінченням залежно від сеансу (`*.ngrok-free.app` або `*.ngrok-free.dev`) — `ngrok-on.sh` дозволяє обидва. Якщо колись з'явиться ще один варіант і сайт не відкриється (в консолі браузера буде "Blocked cross-origin request"), дописати його в `allowedDevOrigins` вручну в `frontend/next.config.ts` і перезапустити frontend.

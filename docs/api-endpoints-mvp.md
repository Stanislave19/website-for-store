# API-ендпоінти — MVP

> REST API, яке FastAPI віддає фронтенду (Next.js). Базовий префікс: `/api`. Формат обміну — JSON.
> Ендпоінти діляться на **публічні** (вітрина) і **захищені** (адмінка, потребують автентифікації менеджера/власника).

## Позначення

- Метод: GET (отримати), POST (створити), PATCH (частково змінити), DELETE (видалити)
- 🔓 — публічний (доступний усім)
- 🔒 — захищений (тільки персонал: manager / owner)
- `{id}` — підставляється конкретне число (id запису); `{slug}` — текстовий SEO-ідентифікатор

---

## 1. Каталог і товари (вітрина)

**🔓 GET `/api/products`** — список товарів каталогу
Параметри (query): фільтри й пагінація
- `category`, `brand`, `gender`, `mechanism`, `version` — фільтри-довідники
- `price_min`, `price_max` — діапазон ціни
- `diameter_min`, `diameter_max` — діапазон діаметра
- `thickness_min`, `thickness_max` — діапазон товщини корпусу (те саме, що діаметр, окреме число, не EAV)
- `attribute_value_ids` — значення EAV-атрибутів (матеріал, форма, скло, водозахист, колір циферблата, індикація, ремінець, функції, тип індексів). Для атрибута з кількома вибраними значеннями ОДНОГО типу (напр. «Функції»: Хронограф + Дата) логіка — «АБО» (товар підходить, якщо має хоч одне з обраних значень цього типу); між РІЗНИМИ типами атрибутів — «І» (кожен обраний тип має збігтися).
- `search` — пошук по назві та бренду
- `sort` — сортування (`price_asc`, `price_desc`, `newest`)
- `page`, `page_size` — пагінація
Повертає: список товарів (id, slug, назва, короткий опис, ціна, old_price, головне фото, бренд) + загальну кількість + кількість сторінок. `slug` потрібен, щоб побудувати посилання з каталогу на картку товару (`/product/{slug}`).

**🔓 GET `/api/products/{slug}`** — повна картка товару за slug
Товар адресується за полем `slug` (SEO-URL, напр. `/api/products/casio-mtp-1234`), не за числовим id.
Повертає: усі поля товару, усі фото, усі атрибути (EAV), бренд, категорію, механізм, гарантію, комплектацію.

**🔓 GET `/api/categories`** — дерево категорій і підкатегорій
Повертає: категорії з вкладеністю (parent_id), для меню й фільтра.

**🔓 GET `/api/filters`** — доступні значення фільтрів із лічильниками
Повертає:
- Категорійні фільтри (бренд, механізм, версія, матеріал, форма, скло, водозахист, колір циферблата, індикація, ремінець, функції, тип індексів, стать) — список значень + кількість товарів на кожне (як «Латунь (1554)» у ДЕКА). Формат відповіді ОДНАКОВИЙ для всіх, включно з «Функції» — множинність вибору це властивість того, як фронтенд малює й відправляє фільтр (чекбокси замість радіо-кнопок), а не окремий формат відповіді API. Нові типи атрибутів (`attribute_types`) підхоплюються в цьому списку автоматично — жодних змін коду при додаванні нового типу не потрібно, доки хоч один товар має значення цього типу.
- Числові фільтри (ціна, діаметр, товщина корпусу) — min/max діапазон (не список), для повзунка/діапазонних кнопок.
Потрібно, щоб намалювати панель фільтрів.

> Поведінка підкатегорій: фільтр за батьківською категорією показує товари з УСІХ її дочірніх підкатегорій (рекурсивно), а не лише прямо прив'язані до батька. Зафіксувати як явну логіку вибірки.

## 2. Кошик і промокоди

Кошик живе на фронті (у браузері) — окремих ендпоінтів на зберігання не потребує. Бекенд лише перевіряє промокод і рахує підсумок.

**🔓 POST `/api/cart/validate-promo`** — перевірити промокод
Тіло: `{ code, cart_total }`
Повертає: чи валідний, тип і розмір знижки, підсумкову суму зі знижкою — або помилку (не існує / прострочений / ліміт вичерпано).

---

## 3. Доставка — автопідказки Нової Пошти

**🔓 GET `/api/delivery/cities`** — пошук міст
Параметр (query): `query` — введений клієнтом текст.
Повертає: список `{ ref, name }` — `ref` це внутрішній ідентифікатор міста в Нової Пошти, `name` — назва для показу. Порожній запит або запит < 2 символів повертає порожній список (не викликає зовнішнє API).
Проксі до API Нової Пошти (`Address.getCities`) з кешем на 5 хв. Якщо API Нової Пошти недоступне — повертає порожній список (200), не помилку.

**🔓 GET `/api/delivery/warehouses`** — пошук відділень
Параметри (query): `city_ref` (обов'язковий, з відповіді `/api/delivery/cities`), `query` — текст пошуку.
Повертає: список `{ ref, number, description }`. Без `query` повертає порожній список навмисно (для великих міст Нова Пошта віддає тисячі відділень одним запитом — без тексту пошуку список не запитується).
Проксі до `Address.getWarehouses`, той самий кеш і поведінка при недоступності API.

## 4. Оформлення замовлення (заявка)

**🔓 POST `/api/orders`** — створити заявку
Тіло: товари (id + кількість), ім'я, прізвище, телефон (+380), місто, `city_ref` (опційно), спосіб доставки, відділення НП (якщо НП), `warehouse_ref` (опційно), спосіб зв'язку, коментар, промокод (опційно), user_id (якщо залогінений).
`city_ref`/`warehouse_ref` — внутрішні ідентифікатори Нової Пошти; заповнюються, коли клієнт обирає місто/відділення з автопідказки (не при ручному введенні тексту чи для інших способів доставки). Використовуються менеджером для точного створення ТТН.
Дії бекенду: валідує телефон, рахує items_total / discount / total, зберігає замовлення зі статусом `new`, шле Telegram-сповіщення менеджеру.
Telegram-повідомлення містить: номер заявки, список моделей (назва + артикул + ціна), суму замовлення (з промокодом, якщо був), ім'я та прізвище, телефон, місто, спосіб доставки, відділення НП, бажаний спосіб зв'язку, коментар.
Повертає: номер заявки (для екрана-підтвердження).

## 5. Список бажань (тільки залогінені)

> Гостьовий wishlist живе в браузері — ендпоінтів не потребує. Ці — для клієнтів з акаунтом.

**🔒(клієнт) GET `/api/wishlist`** — список бажань клієнта

## 8. Адмінка — автентифікація

**🔓 POST `/api/admin/login`** — вхід персоналу (окремий від клієнтського)
- Якщо у користувача 2FA вимкнена — повертає повний JWT-токен одразу.
- Якщо у власника `two_factor_enabled = true` — повертає НЕ повний токен, а `{ requires_2fa: true, temp_token }`. Повний токен видається лише після `/2fa/challenge` з temp_token + правильним TOTP-кодом. Це гарантує, що 2FA реально блокує вхід, а не є формальністю.
Усі ендпоінти нижче потребують повного токена (роль manager або owner).

**🔒(owner) POST `/api/admin/2fa/setup`** — увімкнути двофакторку: генерує TOTP-секрет, повертає QR-код для застосунку-автентифікатора.
**🔒(owner) POST `/api/admin/2fa/verify`** — підтвердити код і активувати 2FA.
**🔓 POST `/api/admin/2fa/challenge`** — другий крок входу власника: приймає temp_token + TOTP-код, повертає повний JWT.

## 9. Адмінка — товари

**🔒 GET `/api/admin/products`** — список товарів (з пагінацією, пошуком)
**🔒 POST `/api/admin/products`** — створити товар
**🔒 PATCH `/api/admin/products/{id}`** — редагувати товар
**🔒 DELETE `/api/admin/products/{id}`** — видалити товар
**🔒 POST `/api/admin/products/{id}/images`** — завантажити фото товару
**🔒 DELETE `/api/admin/products/{id}/images/{image_id}`** — видалити фото
**🔒 POST `/api/admin/products/import`** — масовий імпорт з Excel/CSV
Тіло: файл. Дії: читає рядки, upsert довідників (бренд/механізм/атрибути — знаходить або створює), створює товари. Повертає звіт (скільки додано, помилки).

## Загальні технічні правила

- Автентифікація: токен (JWT) у заголовку. Клієнтські й адмінські токени розділені.
- Валідація вхідних даних — Pydantic (телефон +380, обов'язкові поля, enum-значення).
- Помилки — стандартні HTTP-коди (400 — невірні дані, 401 — не авторизований, 403 — немає прав, 404 — не знайдено).
- Пагінація скрізь, де списки (каталог, замовлення, товари в адмінці) — 1000+ товарів.
- CORS налаштувати для домену фронтенду.
